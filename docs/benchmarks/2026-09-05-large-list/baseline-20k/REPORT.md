# ZeroList 실행 비교

Android 16 arm64 에뮬레이터 emulator-5554, 1080×2400. 설치된 release APK와 로컬 APK의 SHA-256 일치: `046ccf593e83123b25642994356c69f603e44fb5ad7ffe35880d1e52cf15f2b1`.

기존 빌드 산출물을 테스트했으며 현재 소스에서 새로 빌드하지 않았다. 로컬 package.json에는 RN 0.85.0, LegendList 2.0.19, FlashList 2.3.1이 지정되어 있다. APK 내부 의존성 버전까지 별도로 추출 검증하지는 않았다.

고정 높이 데이터 20,000개, complex 셀, 엔진별 5회. 매 회 앱 재시작, 3초 준비 후 4회 동일 좌표(540,1800→540,600), 300ms 스와이프. 실행 순서를 회차별 순환했다. 엔진별 스크롤 물리/이벤트 스케줄링은 달라 같은 입력이 정확히 같은 이동 거리를 보장하지 않는다.

프레임은 adb dumpsys gfxinfo, JS 횟수는 기존 [JS0] 계측의 스크롤 전후 차이. JS 콜백은 목록별 서로 다른 의미(scroll 또는 recycle)이며, 횟수를 CPU 시간으로 해석하면 안 된다. 아래 시간/지연률은 각 run의 값에 대한 중앙값.

## 해석과 한계

- ZigPool은 스크롤 이후 추가 마운트가 없고 JS 콜백 수가 적었다. 새 내용의 React 셀 렌더 횟수는 비슷했다. 이번 조건에서 프레임 지연률 우위는 확인되지 않았다.
- 1회차 스크롤 종료 후 스크린샷과 UI 계층을 확인했다. ZigPool과 FlatList 이미지에서 고정 88dp 행을 넘어서는 내용 겹침이 보였다. 완전한 UI 정합성을 통과한 제품 비교가 아니다.
- 빠른 이동 도중 일시적인 잘못된 내용 표시 여부는 이번 정지 스크린샷으로 검증할 수 없다. 실시간 프레임-항목 ID 대응 계측이 추가로 필요하다.
- ZigPool의 프레임 수는 run별로 다를 수 있다. 짧은 샘플과 스크롤 물리 차이를 포함하므로 우열의 통계적 확증으로 쓰지 않는다.
- JS 인위적 정지, dynamic 높이, 저사양 실기기, 장시간 발열/메모리는 테스트하지 않았다.
- 결과는 동일 emulator에서 해당 기존 하네스를 실행한 관측이다. emulator 상대순위도 실기기 상대순위를 보장하지 않는다.
