# 시작 속도와 스크롤 지연 재검증

메모리 개선 버전이 시작 속도에도 이점이 있는지, 앞선 Android 지연 프레임 감소가 반복되는지 확인한다. 최적화 후보를 더 바꾸지 않고 두 엔진에 같은 진단 계측을 추가한 바이너리로 비교한다.

## 시작 시간의 경계

- `native_start`: Android SoloActivity의 onCreate 진입, iOS AppDelegate의 didFinishLaunching 진입. OS의 프로세스 생성과 그 전 초기화는 포함하지 않는다. 플랫폼 간 절대값을 직접 비교하지 않는다.
- `render_begin`: 공통 데이터 생성 후 템플릿 엔진의 첫 React 렌더 진입. JS와 네이티브의 같은 기기 벽시계로 차이를 구한다.
- `data_ready`: UI 런타임에서 전체 배열의 길이를 읽을 수 있게 된 시점. 모든 객체를 미리 평가했다거나 모든 화면의 네이티브 뷰가 완성됐다는 뜻은 아니다.
- `content_ready`: 네이티브 검사에서 현재 화면의 제목·위치가 기대값과 일치하고, 공백과 겹침이 2px 이하이며 가시 항목이 모두 준비된 첫 시점. Android OnDraw, iOS CADisplayLink에서 검사한다. 네이티브 단조 시계로 시작부터의 시간을 구한다.
- 데이터와 내용 모두 준비: 위 두 시점 중 늦은 값. 초기 화면은 초기 슬롯 데이터로 먼저 보일 수 있어 데이터 준비와 나눠 보고한다.

첫 내용 확인은 **실제 GPU 제출 완료나 패널 표시 시각이 아니다.** 본문·합계·색상의 전 프레임 검사는 하지 않는다. 외부 명령 요청부터 두 준비 로그를 읽을 때까지의 시간도 원자료에 남기지만, CLI·콘솔 전달·20ms 폴링 비용이 있어 주 지표로 쓰지 않는다. 앱 전체 콜드 스타트 또는 사용자 터치부터의 시간으로 부르지 않는다.

## 조건

- RN 0.87.1, Reanimated 4.6.0, Worklets 0.12.1, Android/iOS arm64 Release.
- 기존 UI 워클릿과 메모리 개선 UI 워클릿, 실제 데이터 10만 건, 무거운 셀, 동일한 14개 슬롯.
- 시작: 매번 앱 프로세스를 종료한 뒤 재실행한다. 플랫폼·엔진별 첫 1회는 준비 실행으로 보존하되 평균에서 제외한다. 이후 엔진 순서를 번갈아 각 10회 실행한다. 디스크/OS 캐시를 지우지는 않는다.
- 시작 측정에는 JS 인위 부하·스크롤·메모리 조회·녹화를 넣지 않는다. 공통 화면 검사와 시작 진단을 켠다. 시작 후 0.6초의 화면 정확성도 보존한다.
- 스크롤 비용: 시작 진단과 화면 검사를 끄고 기존 준비 12회·측정 18회 스와이프를 사용한다. 평상시/JS 160ms 점유·40ms 여유를 각 엔진·플랫폼 5회씩 비교한다.
- 정확성: JS 점유 상태에서 엔진·플랫폼별 1회 화면 검사를 추가한다. 비용 검사와 분리한다.
- 전체는 시작 40회 + 스크롤 비용 40회 + 정확성 4회, 별도 준비 시작 4회다. 한 번에 한 플랫폼 앱만 실행한다.

주 비교 종료 후 Android 점유 조건에서 개선 후보의 한 실행이 지연 8%를 기록했다. 같은 시점 외부 Zig 빌드·테스트와 호스트 부하 상승이 기록됐다. 외부 부하가 원인이라고 확정하지 않으며, 해당 결과를 제외하지 않는다. 결과의 민감도를 보기 위해 조건을 유지한 보조 비교를 각 엔진 3회, 총 6회로 고정해 추가했다. 보조 결과는 주 비교 평균에 섞거나 대체하지 않는다. 총 정식·보조 90회와 별도 준비 4회다.

시작 시간은 10회 중앙값과 최솟값·최댓값, 동일 회차의 개선 횟수를 함께 보고한다. 스크롤 지연은 5회 평균과 범위를 보고한다. Android gfxinfo 지연 프레임과 iOS CADisplayLink 지연 콜백은 서로 다른 지표다. 호스트의 외부 작업을 통제하지 못했으며 실행 전후 프로세스 이름·부하를 보존한다. 에뮬레이터 결과를 실물 구형 기기의 속도나 전력 우위로 일반화하지 않는다.

## 재현

`OUT_ROOT=<새 경로> python3 -I docs/benchmarks/2026-09-06-startup-speed/run.py`

계측은 `diagnostic=trace-startup`와 공통 화면 검사를 함께 켰을 때 사용한다. 재활용 요청·데이터 포맷·GPU 경로의 최적화 동작은 변경하지 않았다. 원자료에는 초기 준비 실행과 콘솔 연결 실패가 있다면 그 기록도 보존한다.
