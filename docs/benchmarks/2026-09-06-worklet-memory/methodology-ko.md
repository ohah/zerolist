# UI 워클릿 메모리 감소 실험

## 바뀐 경로

기존 `template-worklet`은 JS의 `Item[]` 전체를 `useSharedValue`에 넣는다. Worklets가 각 객체와 속성을 재귀적으로 전달할 수 있게 변환하는 비용이 발생한다.

새 `template-compact`는 다음 순서로 실제 데이터를 전달한다.

1. JS에서 ID·제목·본문·높이·색상을 각각의 배열로 모은다.
2. 필드별 배열을 JSON 문자열 하나로 직렬화해 `scheduleOnUI`의 일회성 인수로 전달한다.
3. UI 런타임에서 복원한 배열을 UI 소유 shared value에 저장한다. 전달 문자열과 JS의 임시 배열은 장기 상태에 보관하지 않아 이후 GC가 회수할 수 있다.
4. 표시할 슬롯의 항목만 작은 객체로 조립한다. React 초기 평가에서는 슬롯의 초기 항목을 사용해 UI의 전체 배열을 JS로 다시 복사하지 않는다.
5. 초기 복원 중 들어온 재활용 요청은 저장하되, 데이터와 내용이 준비되는 갱신에서 매핑을 공개한다.

모든 실제 값과 10만 건의 데이터 접근을 유지한다. 스크롤 도중 JS에 다음 페이지를 요청하는 경로는 추가하지 않았다. 두 워클릿 후보의 풀, 셀 구조, 전용 텍스트, 이미지, 64개 색상 뷰, 4,000회 연산은 같다. GPU API 변경은 없다. 문자열을 사전으로 대체하거나 ID로 내용을 다시 만드는 방식은 사용하지 않았다.

비교 옵션을 유지했고 일반 리스트 기본값은 바꾸지 않았다. 이 방식은 **복사를 없애는 zero-copy 구현이 아니다.** JSON 변환과 UI 복원 비용을 지불하면서 전달 객체 수와 장기 보관량을 줄이는 실험이다. GC 가능해졌다고 즉시 OS에 메모리가 반환되는 것은 아니다.

## 초기 후보와 최종 후보

처음에는 전체 객체 배열을 JSON으로 보내 shared value에 문자열을 계속 보관했다. iOS 예비 검사 1회에서 내용 오류·공백은 0이었으나 종료 RSS가 약 567MiB였다. 최종 후보는 일회성 전달과 필드별 배열로 바꿨다. 예비 결과는 정식 비교 평균에서 제외했다. 예비 소스 변경은 `retained-json-source.zip` 안의 패치에 남겼다.

Reanimated의 `useDerivedValue`는 JS에서도 초기 평가한다. 초기 평가에서 전체 JSON을 복원하면 다시 큰 객체 배열이 런타임 사이에 전달될 수 있어, 최종 후보는 빈 shared value를 만들고 UI 작업 안에서만 복원한다. 슬롯의 초기 평가도 UI 배열 전체를 JS로 읽지 않도록 했다. 같은 방어 처리를 기존 템플릿에도 적용했으므로 과거 수치 대신 **새 바이너리에서 다시 측정한 기존 템플릿**과 비교한다.

## 비교 조건

- RN 0.87.1, Reanimated 4.6.0, Worklets 0.12.1. Android/iOS arm64 Release, 에뮬레이터/시뮬레이터.
- 주 비교: 기존 ZigPool, 기존 UI 워클릿, 메모리 개선 UI 워클릿. 10만 건 무거운 셀, 한쪽 여유 5행, 실제 슬롯 14개. 각 조건 3회.
- 화면 검사: JS 160ms 점유/40ms 여유에서 제목·위치 일치, 공백, 겹침을 관측한다. 각 실행은 준비 스와이프 12회 후 정량 스와이프 18회다.
- 비용 검사: 화면 검사를 끄고 평상시와 JS 점유 조건을 분리한다. CPU는 코어 하나 100% 기준 앱 전체 CPU다. 메모리는 Android 종료 PSS, iOS 종료 RSS다. 서로 같은 지표가 아니다.
- 단순 셀 확인은 양쪽 템플릿·플랫폼별 1회이며 주 비교에 섞지 않는다.
- 시작 메모리: 각 엔진·플랫폼 2회, 앱 실행 요청 후 8초 동안 외부에서 표본을 얻는다. 조회 사이에 100ms를 쉬며 조회 자체의 시간도 기록한다. **관측 최고치**로, 짧은 순간 피크를 놓칠 수 있다. 스크롤·JS 점유·화면 검사는 꺼 둔다.
- 초기 변환 로그: encode는 JS의 배열 구성과 JSON 변환, decode는 UI의 JSON 복원과 공유값 대입 시간이다. 전송 대기, React 첫 화면, 앱 시작 전체 시간을 뜻하지 않는다. UI 복원 작업은 UI 스레드를 점유한다.

호스트의 외부 작업은 완전히 통제하지 못했다. 주 비교의 각 실행 전후 CPU 부하와 프로세스 이름을 남겼으며, 비용 결과는 탐색값이다. 메모리·CPU 표본을 얻는 실행과 녹화는 분리한다. CPU나 시뮬레이터 결과를 실물 구형 태블릿의 전력·발열·속도 우위로 일반화하지 않는다.

## 정확성과 한계

숫자와 문자열은 원본 `Item`의 값을 보존한다. 테스트는 인덱스와 다른 ID, 한글·이모지·줄바꿈·따옴표, 빈 문자열, 소수 값, 반복 항목과 빈 배열을 확인한다. 런타임 화면 검사는 실제 네이티브 제목을 읽는다. 본문·합계·색상의 전 프레임 자동 검사는 하지 않는다.

지원 범위는 고정 높이 simple/heavy의 Solo 측정이다. 동적 높이, 임의 React 자식, 데이터 삽입·삭제·정렬의 전체 원자성, 반복 마운트의 장시간 누수, 실제 기기 검증은 남아 있다. 일반 리스트 API로 배포한 변경이 아니다.

주 비교는 `run_matrix.py`, 단순 셀과 시작 메모리는 `extra.py`로 재실행한다. 초기/준비 로그는 `*-startup.log`, 실제 정량 구간은 `*-measured.log`다. 원자료의 과거 결과를 새 후보 결과로 덮어쓰지 않는다.
