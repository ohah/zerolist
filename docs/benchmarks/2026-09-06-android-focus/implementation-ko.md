# Android 네이티브 풀의 배치 비용 감소

공개 ZeroList API, 준비 행 수, 항목 key와 React 상태 초기화 정책을 유지하면서 Android 내부 배치를 변경했다. GPU API·그래픽 백엔드는 바꾸지 않았다. iOS 구현은 이번 수정에 포함하지 않았다.

## 변경

1. 스크롤의 공통 이동을 부모 View의 `scrollTo`로 처리한다. 이전에는 매 프레임 모든 풀 자식의 `translationY`에 스크롤 위치를 차감했다. 이제 같은 항목을 맡는 자식의 변환 값은 대부분 유지되며, 부모가 한 번 이동한다.
2. 먼 인덱스로 이동할 때 기준 좌표를 현재 스크롤 위치로 다시 잡는다. 큰 데이터의 절대 위치를 그대로 float으로 저장하지 않고 차이를 계산한 뒤 변환해 정밀도 손실을 막는다. 클리핑과 내부 화면 검사도 부모 스크롤 좌표를 반영한다.
3. Fabric이 RN 자식의 크기와 위치를 결정한 뒤 FrameLayout이 다시 측정·배치하던 중복 경로를 제거한다. 부모는 전달받은 크기를 사용하고 자식 배치는 Fabric에 맡긴다. RN의 ReactViewGroup도 이 소유 관계를 따른다.

예제의 기존 ZigPool 비교 어댑터도 같은 네이티브 뷰를 사용하므로 최종 바이너리에서는 이 배치 변경을 함께 받는다. 다만 통합 ZeroList의 항목 상태 보호·스크롤 콜백 등과는 여전히 기능이 다르다.

## 같은 APK에서 비교하는 진단 경로

라이브러리의 공개 props로 엔진을 고르는 기능은 없다. 예제 Activity의 diagnostic 인자로만 대조 실험한다.

| 최종 바이너리 diagnostic | 부모 스크롤    | Fabric 단독 배치 |
| ------------------------ | -------------- | ---------------- |
| normal / 일반 앱         | 사용           | 사용             |
| pool-baseline            | 이전 셀별 이동 | 이전 중복 배치   |
| pool-parent-scroll       | 사용           | 이전 중복 배치   |
| pool-fabric-layout       | 이전 셀별 이동 | 사용             |

후보 바이너리는 기본값 변경 전이라 `normal`이 이전 경로이고 `pool-combined`가 두 변경을 함께 켠 경로다. [후보 소스](candidate-native.kt.txt)와 APK 해시는 별도로 보존한다. 최종 비교의 `zerolist-before-5`는 최종 APK의 `pool-baseline`이다. 이전 제품 전체로 되돌린 비교가 아니라 이번 두 네이티브 변경만 끈 비교다.

## 검증 범위

104개 기존 테스트, lint·타입 검사, Android arm64 Release 빌드가 통과했다. 실제 에뮬레이터에서 재정렬·앞 삽입·내용 교체·비우기·복원·동적 높이 변경을 다시 녹화했다.

추가 화면에서는 10만 건의 99,980번 위치로 이동하고 화면을 눌러 해당 항목의 선택 값이 1이 되는 것을 확인했다. 앞 삽입 후에도 항목 99,980의 상태가 유지됐다. 먼 위치에서 데이터 20개로 축소, 처음 이동, 고정 높이 100→140 변경, 끝 이동도 실제 화면으로 확인했다. [자동 로그 검사](contract-results.json). `measureInWindow` 좌표는 풀의 실제 표시 위치 판정에 쓰지 않았다.

실물 저사양 기기, 전력·시작 중 최대 메모리·긴 동적 변경은 미검증이다. 내부 풀/호환 경로 전환 시 상태와 스크롤 위치 이전 등 기존 제한도 남아 있다. Android/iOS 앱 빌드 CI는 추가하지 않았다.

## 회수한 React 슬롯 memo

변경되지 않은 슬롯의 View/Fragment 처리를 생략하는 후보도 구현·검사했다. 항목 key 초기화는 유지했지만 긴 스크롤 비교에서 이점이 유지되지 않아 최종 소스에서는 제거했다. 후보 패치와 18회 유효 측정 자료를 보존한다. 공개 API에 memo 선택 옵션은 추가하지 않았다.
